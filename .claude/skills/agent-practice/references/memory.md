# Memory 系统详解

## 文件派 vs 数据库派

| 维度 | 文件派（Claude Code 风格） | 数据库派（OpenClaw 风格） |
|------|--------------------------|------------------------|
| 存储 | MEMORY.md 索引 + 独立 `.md` 文件 | SQLite + 向量（sqlite-vec）|
| 检索 | 关键词 / 全量加载 | 向量相似度 + BM25 混合 |
| 适用 | 简单场景，单用户 | 跨会话语义检索，多用户 |
| 上限 | 200 行强制约束 | 时间衰减 + Memory Flush |
| 写入控制 | 手动 + AI 辅助 | 自动提取 + 质量过滤 |

## MEMORY.md 文件格式（文件派）

```markdown
---
name: user-preference-dark-mode
description: 用户偏好暗色主题，所有 UI 代码默认使用 dark variant
metadata:
  type: user
---

用户明确要求所有界面使用暗色主题。生成 UI 代码时默认选 dark variant，
CSS 变量用 `--color-bg-dark`。

**Why:** 用户在 2026-03 明确说"所有界面都要暗色"。
**How to apply:** 每次生成 UI 组件时检查是否有 dark mode 支持。
```

**保存规则**：
- 能从代码/git/文档推导出的 → 不存
- 只对当前对话有用的 → 不存
- 存发现的非显然事实、用户偏好、项目约束

## 混合检索配置（数据库派）

```typescript
// 向量 70% + 关键词 30%
const results = await hybridSearch(query, {
  vectorWeight: 0.7,
  bm25Weight: 0.3,
  timeDecay: true,       // 旧记忆权重递减
  maxResults: 10,
});
```

## 五种失效模式与应对

| 失效模式 | 表现 | 解法 |
|---------|------|------|
| **污染** | 错误信息被记忆 | 写入时质量校验，允许覆盖修正 |
| **爆炸** | 记忆数量失控 | 上限 + 定期 Memory Flush 压缩 |
| **过期** | 记忆与现实不符 | TTL 机制，重要记忆定期 revalidate |
| **新旧冲突** | 矛盾记忆共存 | 写入时检测相似记忆，合并或替换 |
| **新项目陌生感** | 跨项目记忆污染 | 记忆按项目隔离，命名空间区分 |

## Memory Flush（压缩前必做）

在 LLM 摘要压缩之前，先提取值得长期保留的信息写入记忆文件。  
避免压缩导致信息永久丢失——摘要会抛弃细节，记忆文件不会。

## RAG 六步流程（数据库派）

```
1. 加载文档（PDF/MD/代码）
2. 分块（递归段落切块 > 语义切块，误差不累积）
3. 向量化（text-embedding-3-small 或本地模型）
4. 存储（SQLite + sqlite-vec）
5. 检索（混合：向量相似度 + BM25）
6. 注入（JIT 注入相关块，不是全量塞入）
```

分块推荐：递归段落分块准确率 ~69%，优于语义分块 ~54%。
