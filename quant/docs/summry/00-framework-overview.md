# 策略验证框架 — 架构总览

## 1. 问题定义

| 错误目标 | 正确目标 |
|---|---|
| 把 CAN SLIM / 突破 / 价值投资写成固定模板上线 | 提供**可配置、可校验、可回测、可归档**的验证平台 |
| 因书中有某策略就新增 Python 文件 | **规则进数据库**；代码只提供通用算子 |
| 一次漂亮回测 = 策略有效 | **证据状态机 + 样本外 + 否决条件 + 试验账本** |

## 3. 核心契约

### 3.1 数据库是策略定义的唯一事实来源

`quant_strategy.spec` 保存完整 StrategySpec JSON。  
**不为每本书、每个候选新建 `strategies/foo.py`。**

遗留 `app/strategy/strategies/*.py` 仅作回归对照，新路径走 Spec 编译。

### 3.2 动态 ≠ 任意代码

| 允许 | 禁止 |
|---|---|
| 白名单操作符 AST | Python / SQL / JS `eval` |
| 目录内字段 | 任意列名、网络、文件 IO |
| 有界窗口与参数扫描 | 无限组合、无限嵌套 |

### 3.3 完整策略最低组成

可启用 / 可回测的策略必须同时具备：

1. 股票池与资格过滤  
2. 进场条件（布尔表达式）  
3. 初始仓位或组合权重规则  
4. **原生离场**（或组合调仓能完整表达进出）  
5. 成交语义（系统默认 T+1）  
6. 验证段（基线、OOS、否决条件可选但推荐）

只有因子/进场/止损的半成品 → 能力解析应拒绝或仅作研究草稿。

### 3.4 三类离场分开统计

| 类型 | 含义 | 例 |
|---|---|---|
| 原生离场 | 策略假设失效 | 跌破 10 日低点 |
| 风险覆盖 | 路径保护，不否定假设 | ATR 止损 |
| 强制/运营 | 池外、ST、数据失效 | 退出成分股 |

## 4. 能力解析（保存/回测前闸门）

| 状态 | 含义 | UI 行为 |
|---|---|---|
| `supported` | 数据+引擎就绪 | 允许回测/实验 |
| `missing_data` | 缺字段/点时数据 | 阻止回测，提示缺口 |
| `missing_engine` | 缺操作符 | 阻止回测，走扩组件 |
| `subjective_only` | 无法机器定义 | 不进自动回测 |
| `boundary_denied` | 越产品边界 | 不开发 |

## 5. 产品边界（框架硬约束）

- A 股日频研究 + 模拟回测  
- 不做券商连接、下单、半自动执行  
- 不做期权链/高频盘口执行  
- `quant_trade` 仅手工记账  

框架产出的是 **研究证据**，不是交易指令。
