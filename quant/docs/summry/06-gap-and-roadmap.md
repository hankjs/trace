## 3. 90 天框架路线（建议）

```text
Week 1-2   验证清单硬校验 + 回测/实验证据展示打磨
Week 3-4   常用 Spec 片段库（突破、均线、RSI 恢复）— 仍是 JSON 片段
Week 5-6   扩展 2～3 个高复用算子 + 1 个新基线
Week 7-8   实验对比与多重检验结果挂 UI
Week 9-12  按验证队列需要补字段（而非按书补字段）
```

## 4. 验收：框架是否「够用」

当满足以下条件，可认为框架达到「可持续验证」：

1. 新策略 **80%** 案例只需前端配置，不发版  
2. 任意回测可回答：规则哈希、算子版本、数据指纹、OOS 结论  
3. 失败 trial 可检索、不可静默删除  
4. 扩一个算子有标准 PR 清单（spec/components/test/editor/catalog）  
5. 产品文案从不把 oos_passed 写成交易建议  

## 5. 与旧 summry 文档的关系

此前「书库正反向成果」仍有参考价值，但**从属于本框架**：

- 原则 → 写入 validation / 实验纪律  
- 反模式 → 否决规则与产品禁止项  
- 候选列表 → 配置队列，不是开发队列
