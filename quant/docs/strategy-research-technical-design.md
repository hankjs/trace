# 策略研究计划技术设计

> 对应需求：`docs/strategy-research-plan.md`
>
> 边界：A 股日频研究、模拟回测与外部手工决策，不包含任何真实交易执行。

## 1. 单一规则来源

策略实例的完整生效参数由模板默认值和实例覆盖值合并得到。统一风险覆盖层与
止盈覆盖层也属于该参数快照，使用 `risk_overlay`、`take_profit` 两个嵌套对象：

```json
{
  "enabled": false,
  "type": "fixed_pct",
  "value": 0.08,
  "atr_period": 14
}
```

`type` 支持 `fixed_pct` 和 `atr_multiple`。页面、信号、计划生成和回测都调用
同一校验与计算实现。覆盖层默认关闭；关闭时不改变模板原生信号。

六个模板在目录元数据中声明研究计划能力，并由适配器计算自己的观察条件和原生
退出语义。只有突破类模板在配置客观容忍参数后生成观察区间；组合模板始终生成
目标权重变化，不生成单股进场区间。

策略版本采用内容哈希，不只依赖参数：版本输入同时包含完整参数快照、计划适配器、
统一覆盖层实现和当前模板源码。规则源码发生变化后，即使数据库中的参数未改，旧
计划与旧回测也不会被误认为同一策略版本。

突破类模板的观察线由模板本身导出，计划适配器与模拟状态机共同读取。配置正数
`max_entry_premium` 后，观察线和上界共同构成 T+1 开盘有效区间；开盘低于观察线
或高于上界都不模拟进入，并要求原生条件重置后再形成新上升沿。该参数因此同时
进入页面、信号、普通回测、批量评估和参数扫描，不是页面专用区间。

## 2. 持久化模型

`quant_research_plan` 保存不可变计划快照：策略实例标识、名称、模板、版本哈希、
完整参数、数据基准日、生成时间、下一模拟成交日、复权口径、状态、观察信息、
风险/止盈/原生退出、退出命中和精确匹配的回测证据。历史计划不依赖当前策略行
重算说明。

`quant_research_plan_item` 保存组合计划的逐股权重变化、评分、排名、资格和原因。
`score_details` 进一步固化每个因子的原始值、权重、贡献值和总分，页面不根据当前
模板重新计算历史评分。
`quant_signal.plan_id` 指向信号当前关联的计划版本。重算产生新快照，并通过
`supersedes_plan_id` 保留版本链；迁移由 Alembic 管理，`sql/init.sql` 保持等价。

`quant_backtest_run` 固化完整参数、费用、逐笔模拟成交和退出原因分布。研究计划
只引用当前查看者自己的、策略版本、参数、覆盖层、费用、单标的代码或组合股票池
全部相同的回测；没有精确匹配时返回“尚未验证”。匹配结果在单次 API 请求内缓存，
不改变精确匹配规则。

每份计划的参数快照还固化生成时的默认佣金、印花税和滑点。即使尚无匹配回测，
页面也展示待验证费用口径；默认费用以后变化时，旧计划仍只匹配旧费用结果。自定义
静态池另存成员集合哈希，同一 `pool_id` 后续被编辑时不会借用旧成员集合的回测。

## 3. 日频状态机

单标的模板先产生原生目标仓位，再应用覆盖层：

1. T 日收盘形成原生入场上升沿，T+1 日开盘按可成交性约束模拟入场。
2. 风险、止盈和原生退出在每日收盘统一确认，T+1 日开盘模拟退出。
3. 同日多条件命中时保存全部原因，主原因按风险、止盈、原生退出排序。
4. 风险或止盈退出后进入“等待重置”，原入场条件必须先失效并再次出现上升沿。
5. T+1 开盘不可卖出时，实际模拟持仓和首次退出原因保持不变，后续交易日开盘
   继续尝试，直到首次满足可成交约束；延迟成交不生成新的退出信号日。
6. 非交易日或行情未更新不生成新计划；过期、条件失效或价格越界只更新研究状态，
   不产生真实动作。

无论覆盖层是否启用，单标的都经过同一模拟入场状态机。T+1 开盘受阻不会被误报成
卖出提示，也不会生成虚假的持仓计划；原入场条件持续为真期间不顺延补入。

策略模拟状态持续为持有时，每个新的有效行情日会生成一份“持有”计划快照，不伪造
新的买入或卖出信号。该快照沿用模拟入场状态，并展示当日可计算的风险、止盈和原生
退出参考；信号计划的版本链不受买卖方向变化限制，保证同一策略与标的持续可追溯。
持有快照的“信号日收盘价”明确为不适用。ATR 覆盖线直接固化状态机在模拟入场时
采用的 ATR 口径；放量突破的模板 ATR 风险线也直接读取模板内部以入场信号价为
基准、只收紧不放宽的真实状态，不使用最新收盘价重新估算。

组合模板先产生计划调仓权重，再逐股应用覆盖层。覆盖退出的股票权重归零并锁定，
最早到下一次模板计划调仓才可重新获得资格。调仓原因使用新增、保留、增仓、减仓、
清仓和风险过滤等结构化类型。每个仍在模拟持有的成分都固化自己的模拟入场价、
风险参考线和止盈参考线；新纳入成分在尚无 T+1 模拟入场价时明确标记为待计算。
股票池成员变化时以前一份计划的逐股目标权重为基线，因此已调出股票仍会作为
目标权重为零的变化项保留，不会从计划中静默消失。

## 4. 模拟撮合与证据

回测沿用 T 日收盘信号、T+1 日开盘成交，计入佣金、印花税和滑点。开盘涨停、
停牌、缺失 bar 或无有效开盘价时，买入信号丢弃且不顺延。开盘跌停、停牌、缺失
bar 或无有效开盘价时，减仓/卖出不成交，保留实际模拟持仓，并在后续首个可成交
交易日开盘继续完成原退出。组合调仓与逐股覆盖退出使用同一约束。

组合目标权重由 vectorbt 转换成实际订单后再做第二次方向校验。原因是其他成分的
价格漂移会让“目标权重未变”的股票在整行调仓时产生真实买单或卖单；约束必须按
实际订单方向判断，不能只比较前后目标权重。不可成交的实际买单丢弃，实际卖单
保留原信号日和原因并顺延。组合计划读取时也逐项检查 T+1 的停牌、有效开盘价及
涨跌停，任一变化项无法按同一假设成交即显示“需要重新评估”。

组合在计划调仓日同时命中 MA20、覆盖层或调仓调出时保留全部原因，仍按风险覆盖层、
止盈、模板原生退出、组合调仓排序。只要存在逐股退出或调出命中，顶层计划状态为
“已触发退出”，不会因为当天也是正常调仓日而显示“当前有效”。

涨跌停幅度按逐日数据判断：当日 ST 为 5%，北交所 `bj.*` 为 30%，创业板
`sz.30*` 与科创板 `sh.688*` 为 20%，其余为 10%；历史 bar 缺少 `is_st` 时按
普通板块比例回退，不能用股票当前 ST 状态回填历史。

组合回测与计划不把结束日股票池快照广播到整个区间。指数池按指定指数的
`in_date/out_date` 成分区间逐日判断；全 A 池按上市满额天数、退市日期和日线中的
历史 ST 状态逐日判断，并把区间内后来退市的股票保留在样本并集中。历史成分或逐日
ST 数据不足时明确报错。停牌日只延续最近一次已确认的 ST 状态，不填造价格。
自定义静态池按用户声明的固定名单贯穿区间，并在 API 与页面显式标记幸存者偏差；
它不作为指数历史成分的替代来源。

逐笔成交明细只记录实际完成的模拟成交，不把不可成交尝试伪造成订单。延迟退出的
`signal_date`、主原因和全部命中原因始终来自最初 T 日收盘触发，`execution_date`
记录最终实际模拟成交日；退出原因分布也只在实际退出成交后计数。不可成交状态由
持仓与待执行退出状态机保留，而不是把计划价格线当作成交价。

逐笔明细区分信号日、模拟成交日、模拟成交价、方向、费用、全部退出原因和主原因。
退出原因分布同时统计主原因与全部命中。区间收益、最大回撤、胜率和交易次数均从
同一次含费用撮合得到。参数扫描接受覆盖层参数，不能绕过统一校验。

## 5. API 契约

- 信号列表返回 `signal_close_price`、中文 `reason_text`、计划 ID、状态和紧凑计划
  摘要，不再对外返回内部 `reason` JSON。
- 计划详情接口按 ID 返回完整快照、结构化计算依据和回测证据。
- 计划列表可按股票、策略、类型和日期过滤，并执行策略可见性隔离。
- 组合计划返回逐股目标权重变化、评分及评分分解、排名、资格、原因，以及原生风险、
  风险覆盖层和止盈覆盖层的具名参考线与数据日期。
- 策略模板和策略实例返回计划能力声明及完整生效覆盖层参数。
- 回测创建与查询返回参数/费用快照、逐笔模拟成交和退出原因分布。

所有对外状态和原因由统一中文词典渲染，不向页面暴露原始内部 JSON。

## 6. 前端工作流

信号列表保持紧凑，通过可键盘操作的行展开依次显示数据与信号、进场观察、风险与
退出、历史验证和产品边界。个股页在 K 线按需叠加可客观计算的线和区间，动态指标
条件放在图表下方；每条线同时显示名称、值和日期。

策略管理将模板原生参数与统一覆盖层分区。覆盖层使用开关，关闭时隐藏无效输入；
公共策略仍只读。回测结果展示完整参数、费用、退出原因分布和逐笔模拟成交。组合
计划使用权重变化表，不复用单标的进场文案。

## 7. 测试与重算

后端测试覆盖：六模板适配器、价格线/无价格线、参数校验、T+1 时序、同日多原因、
退出后重入、组合锁定、精确回测匹配、权限隔离、非交易日、数据不足、迁移与
`sql/init.sql` 等价。前端测试覆盖：展开/收起、键盘焦点、覆盖层开关、中文状态、
无范围时不渲染占位、小屏横向表格和回测明细。

部署先执行 `uv run alembic upgrade head`。研究计划和信号是派生数据，可在保留用户
策略与手工成交记录的前提下清理后按新模型重算；用户策略和 `quant_trade` 永不纳入
重算删除范围。
